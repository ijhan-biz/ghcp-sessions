1. 45명 운영 규칙

전원 공통 트랙

수업 중에는 모두 이 프로젝트의 sessionize를 사용합니다. 개인 프로젝트는 d2-s4-green PASS 후 선택입니다.

강사는 에러코드만 받음

질문은 복구 사다리를 끝낸 뒤 [E-D2S4-GREEN] 명령 + 마지막 8줄 형식으로만 합니다.

시간 하드스톱

세션 종료 +5분 예상이면 컷라인을 실행합니다. 일반 미완은 오류코드로 질문하고, D2·S4 구현 미완만 recover 후 D+7에 재구현합니다.

발표

Day1 발표는 없습니다. Day2 S7은 대표 3명만 3분씩 발표하지만, 슬라이드 3장과 handoff는 전원이 제출합니다.

참고 자료: activity-log 도메인의 개념과 오픈 소스 구현 사례는 ActivityWatch GitHub 저장소의 문서와 코드를 참고할 수 있습니다. 실습 구현에서는 이 프로젝트의 스펙과 gate를 우선합니다.
하지 말 것: 전체 폴더를 Agent에 맡기기 · 다른 참가자 파일 복사 · gate 미통과인데 완료 선언 · 힌트 없이 solution 먼저 열기.

4. 복구 사다리 — 강사에게 묻기 전 필수

  1. npm run lab -- check <step>로 오류코드를 받습니다.
  2. npm run lab -- hint <step> 1을 적용하고 다시 check.
  3. npm run lab -- hint <step> 2를 적용하고 다시 check.
  4. npm run lab -- reset <step>: 현재 파일은 자동 백업되고 starter/baseline으로 돌아갑니다.
  5. npm run lab -- example <step>: 구조 예시를 현재 근거로 바꾸어 다시 작성합니다.
  6. 그래도 막히면 오류코드 형식으로 질문합니다. D2·S4 GREEN만 마지막 수단으로 recover할 수 있습니다.
reset과 recover 차이: reset은 다시 직접 풀기, recover는 solution checkpoint로 진행을 보장하기입니다. recover 사용자는 D+7에서 같은 slice를 다시 구현합니다.

5. 질문 프로토콜 — 이 형식 아니면 먼저 self-check

[오류코드] E-D2S4-GREEN
[실행 명령] npm run lab -- check d2-s4-green
[마지막 로그 8줄] ...
[시도] hint 1 / hint 2 / reset 완료
[질문] 기대값 7/0/0과 다른 한 지점은?

같은 오류코드가 3명 이상이면 강사는 개인 답변 대신 전체에 3분 공지합니다. 오류코드가 다르면 참가자는 계속 개별 복구 사다리를 사용합니다.
