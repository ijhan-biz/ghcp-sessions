이틀 과정을 가상으로 진행해 보고 — 무엇이 걸렸고, 무엇을 고쳤나

15개 세션(Day1 S0~S6 · Day2 S0~S7)을 강사 + 가상 참가자 페르소나 관점으로 시간축을 따라 리허설했습니다. 과정의 5대 약속(역량)에 비추어 부합성을 확인하고, 걸린 지점을 피드백으로 뽑아 실제 콘텐츠를 개선한 뒤 그 변경을 아래에 기록합니다.

대상: GitHub Copilot 중급과정 2일·16h리허설 페르소나 3인발견 6건개선 반영 4건결론: 목적 부합 ✓ (타이밍·인지부하 보정)

리허설 방법 — 어떻게 "가상 진행" 했나

코드를 실제로 실행하는 대신, 각 세션의 학습목표·미니강의·실습 STEP·산출물·컷라인을 읽고 시간 예산·전환·참가자 경험을 시뮬레이션했습니다. 세 페르소나를 동시에 따라갔습니다.

P1 · 준비형본인 기능 스펙 지참, 환경 GREEN. 진도를 앞서감 → 슬랙 타임 필요
P2 · 표준형스펙 초안만, 환경 YELLOW. 컷라인/보강 흐름에 가장 민감
P3 · 폴백형기능 미지참·환경 RED → sample-project-web-curation 폴백. 전환 연속성이 관건
판정 기준: 각 세션이 (a) 시간 안에 산출물을 낼 수 있는가, (b) 앞 세션 산출물을 실제 입력으로 받는가, (c) 뒤처진 참가자에게 명확한 최소 경로(컷라인)가 보이는가 — 세 가지로 봤습니다.

DAY 1 리허설 로그 — 좋은 입력 만들기

시간축 시뮬레이션 · 관찰 · 신호
세션 · 시간리허설 관찰신호
S0 09:00–09:40 (40m)
환경·baseline		도구 버전·setup-mac.sh·baseline·브랜치·Copilot 확인을 40분에 모두. P3(RED)은 자동 설치가 돌면 타임박스를 넘길 위험. 이후 세션이 로컬 환경 필수라 여기서 못 풀면 하루가 흔들림.주의 첫 세션 부하·RED 연쇄
S1 09:40–11:10 (90m)
토큰·가드레일		토큰 절감 3종 + 가드레일 + 비식별화. 분량 적정. P3은 폴백 FEATURE-SPEC.md 채택으로 자연 합류.양호
S2 11:10–12:30 (80m)
프롬프트·AC		R/C/T/C/V/O + User Story + AC + Business Process. 밀도 높지만 컷라인(“User Story 1 + AC 3”) 있어 착지 가능.양호
S3 13:30–14:50 (80m)
리팩토링·Manifest		동작 불변 리팩토링 + Context Manifest + 실패 프롬프트 디버깅. 흐름 자연스러움.양호
S4 14:50–16:30 (100m)
Plan Mode		Plan·Test Matrix·risk tier·rollback을 단일 100분 블록으로. 오후 중반 최장 세션 → 집중 저하. 컷라인은 있으나 “언제 멈춰 쉬는가”가 안 보임.주의 길이·피로
S5 16:30–17:30 (60m)
Spec Pack v1		새 개념 없이 통합 + Handoff 등급(G/Y/R). 하루 마무리로 적절. P2는 여기서 YELLOW 확정 → D2·S0 보강 예약.양호
S6 17:30–18:00 (30m)
QnA·버퍼		Blocker·준비물·한 줄 회고. 버퍼 역할 명확.양호

빌드업 확인: 스펙 카드 → 프롬프트 → AC → Plan/Test Matrix → Feature Spec Pack v1 로 산출물이 실제로 이어짐(각 세션이 앞 산출물을 입력으로 받음). 스레드 끊김 없음.

DAY 2 리허설 로그 — 안전한 실행 · 나만의 솔루션

시간축 시뮬레이션 · 관찰 · 신호
세션 · 시간리허설 관찰신호
S0 09:00–09:30 (30m)
복습·재점검 + SDLC 지도		직전에 추가한 Agentic SDLC 지도(플로우+2표)가 복습·환경 재점검·must-have 좁히기와 같은 30분에 공존. 리허설상 개념 설명이 실습 시간을 잠식. P3(RED) 폴백 전환 시간까지 겹치면 30분 초과.개선 신규 추가분 과부하
S1 09:30–10:40 (70m)
CLI 하네스		권한·로그 플래그 실행 + 로그 해석. gh copilot 미설치 시 Chat fallback 명시. 적정.양호
S2 10:40–12:00 (80m)
Agent Teams·Fleet·Loop		wrapper + policy-check + 역할 5개 + Fleet표 + Loop Canvas + 모델 라우팅. 단일 80분에 개념 6개 — P2/P3 인지 과부하. 게이트 실습 컷라인이 부재(‘Hard gate’만 있고 최소 완료선 없음). 모델 라우팅이 S6과 두 관점으로 중복 → 혼동.개선 과부하·컷라인·중복
S3 13:00–13:50 (50m)
본인 워크플로		반복 업무 분해 + 제약 코드화 + Loop 설계. 컷라인 명확(“업무 1 + 자동화 1 + 중단 1”). P1은 여유 → 확장.양호
S4 13:50–15:10 (80m)
SDD test-first		spec.md → 실패 테스트 → 최소 구현. 폴백은 curate.test.js skip 해제 1사이클. 컷라인(1 AC 1사이클) 명확.양호
S5 15:10–16:20 (70m)
리뷰 패킷		evidence bundle + rollback note + no-cloud attestation. 최소 수료 경로 명시.양호
S6 16:20–17:20 (60m)
Custom Skill/Agent		수료 필수. Skill vs Agent, Fleet 구성, 모델 라우팅 2경로. 자리표시자 재확인 주의 있음.양호
S7 17:20–18:00 (40m)
라이트닝·공유		3장 토크 + 현업 액션 3 + PL handoff + go/no-go. 마무리 적절.양호

목적 부합성 판정 — 5대 약속 대비

역량(약속)담당 세션리허설 판정
1 · 좋은 입력D1 S1~S5충족 토큰·프롬프트·Plan이 Spec Pack v1로 수렴
2 · 안전한 실행D2 S1~S3충족(부하 보정) 하네스·게이트 갖춰짐, 단 S2 밀도 과함
3 · 검증 가능한 변경D2 S4~S5충족 test-first + 리뷰 패킷 + rollback
4 · 나만의 솔루션D2 S3·S6충족 본인 업무 → Custom Skill/Agent 자산화
5 · 경험 공유D2 S7충족 라이트닝 토크 + PL handoff
결론: 5대 약속과 세션 매핑은 빠짐없이 정합합니다. 학습 목표 자체의 누락은 없었고, 발견된 문제는 전부 타이밍·인지부하·최소경로(컷라인) 일관성에 관한 것 — 즉 “무엇을 가르치나”가 아니라 “어떻게 착지시키나”의 문제였습니다. 그 지점을 아래처럼 보정했습니다.

피드백 — 발견 6건

#발견근거(리허설)심각도조치
F1D2·S0 과부하 — 새 SDLC 지도가 30분 복습·환경 세션을 잠식플로우+2표 설명이 실습·폴백 전환 시간과 충돌높음개선 IMP-1
F2D2·S2 인지 과부하 — 80분에 개념 6개, 게이트 실습 최소선 없음‘Hard gate’만 있고 컷라인 부재 → 뒤처진 참가자 착지점 불명확높음개선 IMP-2
F3모델 라우팅(CF-10) 중복 설명 — S2와 S6이 다른 관점으로 각각같은 용어가 두 번, 연결 표지 없어 혼동중간개선 IMP-3
F4D1·S4 길이·피로 — 100분 단일 블록, 휴지점 안 보임최장 세션, 컷라인은 있으나 “언제 멈추나”가 문장에 없음중간개선 IMP-4
F5환경 RED 연쇄 — S0 RED가 이후 로컬 필수 세션으로 전이S0은 TA 큐로 넘기나 복구 없으면 Day2 진행 곤란중간기존 폴백으로 완화(잔여 관찰)
F6교육용 자리표시자 혼동 — model:·policy-check 템플릿이 실제 정책처럼 보일 수 있음재확인 주의가 S7에 몰려 있음낮음IMP-3에 재확인 문구 앞당김

개선 기록 — 무엇을 어떻게 고쳤나 (Before → After)

IMP-1 · D2·S0 시간 배분 명시 F1

Before

SDLC 지도(플로우 + 단계표 + 6레이어표)가 복습·환경 재점검과 같은 30분에 시간 안내 없이 병렬 → 실습 시간 잠식.

After

미니강의 상단에 “시간 배분(30분)” 콜아웃 추가: 지도는 5분 훑기(두 표는 참조용, 암기 X), 나머지 25분은 복습·환경 재점검·must-have. RED면 설명 접고 즉시 폴백.

파일: docs/d2-s0.html · 미니강의 “Agentic SDLC 지도로 오늘 위치 잡기”

IMP-2 · D2·S2 컷라인(최소 완료 경로) 추가 F2

Before

실습 산출물 + ‘Hard gate’만 존재. 뒤처진 참가자의 최소 통과선이 없어 80분 과부하가 곧 미완으로.

After

EV-10 컷라인 콜아웃 추가: “동작하는 policy-check 1개 + Loop Canvas 중단조건 1줄”이면 통과. Fleet표·Agent 매핑은 초안이면 충분 — 동작하는 게이트 하나를 우선.

파일: docs/d2-s2.html · 실습 섹션

IMP-3 · 모델 라우팅 교차참조 + 자리표시자 재확인 앞당김 F3 F6

Before

S2 모델 라우팅 콜아웃이 원칙만 서술 → S6의 구체 설정과 단절, 자리표시자 재확인은 S7에만.

After

S2 콜아웃에 “구체 설정은 S6에서” 교차참조와 “표의 모델·도구 값은 교육용 자리표시자 → 조직 허용 모델·정책 재확인” 문구를 추가해 도입 지점에서 바로 경고.

파일: docs/d2-s2.html · 미니강의 ③ 모델 라우팅 원칙 콜아웃

IMP-4 · D1·S4 중간 브레이크 + 컷라인 가시화 F4

Before

100분 블록에 STEP 1→2→3 연속, 휴지점 표지 없음. 컷라인은 하단에만.

After

STEP 2와 STEP 3 사이에 “중간 브레이크(2분)” 콜아웃 삽입: 절반 지점 알림 + “STEP 2까지가 컷라인” 재강조 + 시간 부족 시 STEP 3~4는 Day2 이월.

파일: docs/d1-s4.html · 실습 STEP 2/3 사이

잔여 관찰(다음 라운드 후보): F5(환경 RED 연쇄)는 현재 폴백·TA 큐로 완화되나, “D1·S0 종료 시점에도 RED면 폴백 환경으로 강제 전환” 같은 명시적 브리지 규칙을 D1·S0/D2·S0에 넣으면 더 견고해집니다. 이번 라운드에서는 범위를 넘어 보류했습니다.
