1. 큰 그림: Copilot의 AI 표면들

VS Code의 Copilot은 하나의 기능이 아니라 여러 AI 표면(surface)의 묶음이다. 공식 문서는 이를 크게 자율적으로 다중 파일 작업을 수행하는 에이전트, 대화형 채팅, 코드 자동완성(inline suggestions), 스마트 액션으로 구분한다. 작업의 성격에 맞는 표면을 고르는 것이 활용의 출발점이다.

자율 · 다중 파일

에이전트가 스스로 컨텍스트를 모으고, 편집하고, 도구를 호출한다. 기능 구현·리팩터링·버그 수정 등 여러 파일에 걸친 작업에 적합.

Agents windowChat view (Agent)

대화형 · 국소

질문·설명·부분 편집을 대화로 처리. 코드 이해, 국소 수정, 빠른 제안에 적합.

AskInline chatQuick Chat

흐름 유지 · 타이핑

타이핑하는 자리에서 다음 코드/편집을 예측. 코드를 직접 쓰는 흐름을 끊지 않는다.

Ghost textNext edit suggestions

단발 · 컨텍스트 액션

커밋 메시지 작성, 코드 설명, 수정 제안 같은 정형 작업을 버튼/메뉴로.

Smart actions
공식 문서 기준 VS Code의 두 주요 에이전트 표면은 Agents window(여러 프로젝트에 걸친 고수준 작업 지향)와 Chat view(에디터 사이드바의 코드 중심 경험)이며, 여기에 경량 표면인 Inline chat과 Quick Chat이 더해진다.

2. 채팅 표면 4종과 사용처

같은 채팅이라도 표면마다 최적 용도가 다르다. 단축키는 macOS 기준이며 괄호는 Windows/Linux다(공식 Docs 표기).

표면여는 법성격추천 사용처
Agents window Preview 타이틀바 Open in Agents · Chat: Open Agents Window · code --agents 채팅을 1차 인터페이스로 삼는 전용 창. 여러 프로젝트에 걸친 작업 오케스트레이션. 여러 repo/작업을 병렬로 돌리는 고수준 태스크, 백그라운드로 긴 작업 위임.
Chat view 타이틀바 채팅 아이콘 · Chat: Open Chat · ⌃⌘I (Ctrl+Alt+I) 에디터 사이드바의 코드 중심 경험. 현재 워크스페이스 작업 보조. 지금 열어둔 프로젝트에서 기능 추가·설명·수정을 대화로 진행하는 일상 작업.
Inline chat ⌘I (Ctrl+I) 편집기/터미널 그 자리에서의 빠른 즉석 편집·제안. 선택한 코드 블록 국소 수정, 터미널 명령 제안 등 흐름을 끊지 않는 소규모 작업.
Quick Chat ⇧⌥⌘L (Ctrl+Shift+Alt+L) 에디터 상단의 경량 채팅 패널. 사이드바를 열지 않고 던지는 짧은 질문/한 줄 요청.
고르는 법 — “이 함수 한 곳만 고치자” → Inline chat. “이 repo에 로그인 기능을 붙이자” → Chat view(Agent). “여러 repo에 걸친 마이그레이션을 밤새 돌리자” → Agents window. “이거 뭐였지?” 한 줄 질문 → Quick Chat.

요청 실행 중 제어: Queue · Steer · Stop and Send

응답이 끝나기 전에도 다음 메시지를 보낼 수 있다. 전송 버튼 드롭다운에서 세 가지 처리 방식을 고른다.

Add to Queue

현재 응답을 방해하지 않고, 끝난 뒤 자동으로 다음 메시지를 보낸다.

Steer with Message

진행 중 도구 실행을 마친 뒤 방향을 즉시 바꾼다. 에이전트가 엉뚱하게 갈 때 궤도 수정용.

Stop and Send

현재 요청을 취소하고 새 메시지를 바로 처리한다.

여러 대기 메시지는 드래그로 순서를 바꿀 수 있고, 기본 동작은 chat.requestQueuing.defaultAction로 steer/queue 중 설정한다.

응답 알림

다른 창/앱에서 일할 때 OS 알림으로 중요한 채팅 이벤트를 받는다. chat.notifyWindowOnResponseReceived(응답 도착), chat.notifyWindowOnConfirmation(입력/승인 필요)로 off / windowNotFocused(기본) / always를 설정한다. 긴 백그라운드 작업을 돌릴 때 always가 유용하다.

3. 코드 자동완성: Ghost text · NES

Copilot은 타이핑하는 동안 코드·주석·테스트 등을 완성하는 AI 인라인 제안을 제공한다. 폭넓은 언어·프레임워크에서 동작하며, 두 종류가 있다.

Ghost text suggestions

커서 위치에 흐린 미리보기 텍스트로 이어질 코드를 제안한다. 한 구간을 자동완성하는 데 강하다.

사용처

보일러플레이트, 반복 패턴, 함수 본문 채우기, 주석 → 코드 변환.

Next edit suggestions (Copilot NES)

지금까지의 편집을 바탕으로 다음 편집의 위치와 내용을 예측한다. 커서에서 떨어진 곳의 편집도 화살표로 안내한다.

사용처

이름 변경 후 연쇄 수정, 시그니처 변경에 따른 호출부 정리 등 “편집이 편집을 부르는” 상황.

인라인 제안은 켜고 끌 수 있고, 제안에 쓰는 AI 모델도 바꿀 수 있다(공식 Docs: Inline Suggestions). Copilot Free는 매월 인라인 제안·AI 크레딧 할당량이 주어진다.

완성 제안은 항상 검토 후 수락한다. 스타일·보안·라이선스 측면에서 그대로 쓰기 부적절한 코드가 섞일 수 있다.

4. Smart actions(스마트 액션)

스마트 액션은 프롬프트를 직접 쓰지 않고도 정형 작업을 실행하는 컨텍스트 액션이다. 코드 완성·에이전트·채팅과 나란히 존재하는 AI 표면 중 하나로 문서에 명시되어 있다.

  • 코드 설명·수정 제안: 편집기 컨텍스트 메뉴/전구(💡) 아이콘에서 호출.
  • 커밋 메시지 생성: Source Control 뷰에서 스테이지된 변경 기반으로 메시지 초안.
  • 정형 반복 작업: 프롬프트를 기억하지 않아도 되는 버튼형 진입점.
사용처 — 리뷰 전 커밋 메시지를 빠르게 뽑거나, 낯선 코드 블록을 오른쪽 클릭 한 번으로 설명받을 때. 프롬프트 작성 부담 없이 자주 쓰는 동작을 처리한다.

5. 내장 에이전트: Agent · Plan · Ask

세션마다 내장 에이전트(Agent, Plan, Ask)를 고르거나, 특정 역할에 특화된 커스텀 에이전트를 쓸 수 있다. 세션 설정에서 에이전트 유형·권한 수준·언어 모델을 함께 지정한다.

에이전트성격추천 사용처
Agent자율적으로 컨텍스트 수집·편집·도구 호출·검증을 반복.여러 파일에 걸친 기능 구현, 리팩터링, 버그 수정, 테스트 작성.
Plan바로 편집하기 전에 접근 계획을 세우는 데 초점.범위가 큰 작업을 착수 전에 단계로 쪼개고 합의할 때.
Ask코드 변경 없이 질문·설명 중심의 대화.코드 이해, 개념 학습, 옵션 비교 등 읽기 위주 작업.
Custom agent보안 전문가·문서 작성자·코드 리뷰어 등 페르소나/역할로 특화.팀 표준에 맞춘 리뷰, 특정 도메인 반복 작업.
에이전트 세션은 Approvals & Permissions로 도구 실행 승인 범위를 정하고, 큰 작업은 Planning·Memory·Subagents로 나눠 처리한다(공식 Docs의 Agents 계열 문서).

6. 컨텍스트 추가 방법

좋은 컨텍스트가 좋은 답을 만든다. VS Code는 여러 방식으로 컨텍스트를 주입한다.

Implicit context

현재 파일·선택 영역·파일 이름을 자동 포함. 에이전트는 필요 시 스스로 컨텍스트를 더 모은다.

#-mentions

입력창에 #로 명시 참조: #file, 폴더, 심볼, #codebase, #terminalSelection, #fetch 같은 도구.

Vision(이미지)

스크린샷·UI 목업을 첨부해 프롬프트 컨텍스트로 사용.

Browser elements

통합 브라우저에서 요소를 선택해 HTML·CSS·스크린샷을 컨텍스트로 추가.

Image carousel Experimental: imageCarousel.chat.enabled를 켜면 채팅 응답의 이미지/영상(예: 통합 브라우저·Playwright·MCP 서버 결과)을 전용 캐러셀 뷰로 본다.

사용처 — 버그 리포트 스크린샷을 붙여 “이 화면의 오류를 재현·수정”을 요청하거나, #codebase로 “이 규칙이 어디에 구현됐는지” 전역 탐색을 시킨다.

7. 도구와 MCP

에이전트는 도구(tools)를 호출해 파일 읽기/쓰기, 터미널 실행, 검색 등을 수행한다. 도구는 내장 도구와 확장/MCP가 기여하는 도구로 나뉜다.

  • MCP 서버: 데이터베이스·API·외부 서비스에 접근하는 도구를 에이전트에 연결. 워크스페이스/사용자 설정으로 구성(공식 Docs: MCP, MCP Configuration).
  • 확장 기여 도구: 마켓플레이스 확장이 제공하는 도구로 능력을 확장.
  • 도구 선택: 채팅에서 사용할 도구 집합을 켜고 끄며, #로 특정 도구를 직접 지목.
사용처 — 사내 이슈 트래커/DB에 MCP로 연결해 “최근 실패한 배포의 로그를 조회하고 원인 후보를 정리”처럼 외부 데이터와 코드를 함께 다루는 작업.
MCP 서버와 확장은 조직 정책으로 제한될 수 있다. 관리자가 허용한 서버·확장만 쓰이며, 신뢰할 수 없는 MCP 서버는 연결하지 않는다.

8. 커스터마이징 7종

에이전트가 처음부터 팀 코드 스타일·관행에 맞춰 동작하도록 조정하는 수단이다(공식 Docs: Agent Customization).

기능무엇추천 사용처
Instructions프로젝트 전역 규칙·컨벤션을 정의(custom instructions).코딩 표준, 금지 패턴, 언어/프레임워크 규칙을 항상 적용.
Prompt files재사용 가능한 단일 프롬프트를 파일로 저장.반복되는 요청(예: “PR 설명 생성”)을 표준화.
Agent skills다단계 워크플로·스크립트·템플릿 파일을 스킬로 패키징.정형 반복 작업(릴리스 노트, 마이그레이션 절차) 자동화.
Custom agents역할/페르소나 특화 에이전트 정의.코드 리뷰어·보안 전문가·테스터 역할 상시화.
Language models작업에 쓸 언어 모델을 선택/구성.비용·속도·품질 트레이드오프에 맞춘 모델 라우팅.
Hooks에이전트 세션의 특정 시점에 스크립트를 실행.편집 전후 검증·포맷·정책 게이트 자동 실행.
Plugins기능 묶음을 플러그인 형태로 확장.팀 공통 도구·워크플로 배포.
사용처 조합 — Instructions로 팀 표준을 고정 + Custom agent로 “코드 리뷰어” 역할 + Hooks로 커밋 전 린트/테스트 게이트 → 일관되고 통제된 에이전트 경험.

9. 세션과 원격 에이전트

여러 세션을 병렬로 돌려 서로 다른 작업을 동시에 진행할 수 있다. 새 세션을 시작해도 이전 세션은 백그라운드로 유지되어 컨텍스트를 잃지 않고 오갈 수 있다.

세션 관리

  • 병렬 세션 실행·전환
  • Session Insights로 세션 현황 파악
  • Sync Sessions로 기기 간 동기화

에이전트 유형

  • Local Agents: 로컬 실행
  • Copilot CLI: 터미널 기반 에이전트
  • Cloud Agents: 클라우드에서 백그라운드 실행
  • Third-Party Agents: 외부 에이전트 연동
사용처 — 세션 A에서 기능 구현을 돌리는 동안 세션 B에서 별개 버그를 수정하고, 긴 리팩터링은 Cloud Agent로 백그라운드에 위임한다. 결과는 알림으로 받아 검토.

10. 변경 검토와 안전 장치

AI가 파일을 바꾼 뒤에는 반드시 검토하고 수락/폐기한다. VS Code는 이를 돕는 장치를 제공한다.

Inline diffs

변경 파일에서 인라인 diff를 보고, 오버레이 컨트롤로 편집을 넘나들며 개별로 Keep/Undo.

Checkpoints

채팅 도중 주요 시점의 파일 스냅샷을 자동 생성해 이전 상태로 롤백.

Stage to accept

Source Control에서 스테이지하면 대기 편집을 수락, 폐기하면 대기 편집도 폐기.

승인·정책

  • Approvals & Permissions: 터미널·편집 등 위험 도구 실행에 승인 요구.
  • 관리자 정책: 에이전트 능력, MCP 서버/확장 제한, 컴플라이언스 강제로 통제된 기본 경험 제공.

문제 진단

Agent Logs는 도구 호출·LLM 요청·프롬프트 파일 탐색을 시간순 이벤트로 보여주고, Chat Debug 뷰는 각 상호작용의 원시 시스템/사용자 프롬프트·컨텍스트·도구 페이로드를 보여준다. 왜 그렇게 답했는지 추적할 때 쓴다.

11. 작업별 활용(테스트·노트북·디버그·브라우저)

공식 Docs의 Guides는 특정 작업에 Copilot을 붙이는 방법을 제시한다. 대표 활용처는 다음과 같다.

테스트

Test-Driven Development, Test with AI로 테스트 생성·보강·실행 보조.

노트북

Edit Notebooks with AI로 Jupyter 노트북 셀 편집·분석 지원.

디버그

Debug with AI로 오류 원인 추적과 수정 제안.

웹앱/브라우저

Test Web Apps with Browser Tools로 통합 브라우저를 통한 UI 확인·요소 컨텍스트 활용. v1.127에서 browser tools가 GA로 기본 활성화(workbench.browser.enableChatTools).

관측성

OpenTelemetry Monitoring 연동으로 에이전트 활동 관측.

비용

Optimize AI Credit Usage로 모델·컨텍스트 선택을 통한 크레딧 절약.

12. 시나리오별 기능 조합

신규 기능 구현

  1. Chat view에서 Plan으로 접근 계획 합의
  2. Agent로 다중 파일 편집 실행
  3. Inline diffs·Checkpoints로 검토·롤백
  4. Smart action으로 커밋 메시지 생성

레거시 코드 이해

  1. Ask + #codebase로 구조 파악
  2. Inline chat로 국소 블록 설명
  3. Prompt file로 “아키텍처 요약” 재사용

병렬 다중 작업

  1. Agents window에서 여러 세션 오케스트레이션
  2. 긴 작업은 Cloud Agent로 위임
  3. 알림(always)으로 완료 감지 후 검토

팀 표준 강제

  1. Instructions로 규칙 고정
  2. Custom agent “리뷰어” 상시화
  3. Hooks로 커밋 전 게이트
  4. 관리자 정책으로 MCP/확장 제한
