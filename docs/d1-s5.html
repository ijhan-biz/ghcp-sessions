오늘 배운 토큰·프롬프트·Plan을 본인 기능 스펙 1건에 모두 적용해 Feature Spec Pack v1을 완성합니다. 이 패킷이 Day2의 입력(handoff)입니다.

  • 토큰 절약 프롬프트·AC·Context Manifest·Plan·Test Matrix를 하나의 패킷으로 묶는다.

미니강의 — 좋은 입력이 Day2 품질을 결정한다

Day2(하네스·SDD)는 "좋은 입력"이 전제입니다. Feature Spec Pack(SD-08)이 약하면 Day2의 구현·테스트 품질도 흔들립니다. 그래서 Day1의 마지막 한 시간은 새로운 것을 배우지 않고, 가진 것을 패킷으로 정리합니다.

이 세션의 실행 코드 (Hands-on)

Feature Spec Pack v1 춨합 + '좋은 입력' 게이트 — 앉 세션 산출물을 묶어 본인 프로젝트의 spec.md로 저장하고, Day1에도 게이트를 한 번 통과해 봅니다.
# 1) 취합: feature-spec-card + context-manifest + plan-and-test-matrix
#    → 본인 프로젝트(없으면 폴백 sample-project-activity-log)의 spec.md 로 저장
# 2) 그 프로젝트에서 '좋은 입력' 게이트 실행 — spec-check는 spec.md 를 자동으로 집습니다
cd sample-project-activity-log     # 본인 기능 폴더가 있으면 그 폴더에서
npm run spec-check                 # 내 spec.md 자가검증: 정상·예외·경계 AC·비식별 확인
#   (labs 데모로 형식만 보려면)  cd labs && npm run spec-check

spec-check가 보완을 표시하면 AC를 정상/예외/경계로 나눠 채우고 다시 실행 → 통과가 '좋은 입력' 검증 목표의 증거입니다. 전체 실습 지도: 각 프로젝트의 README.md.
