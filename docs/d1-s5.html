미니강의 — 좋은 입력이 Day2 품질을 결정한다

Day2(하네스·SDD)는 "좋은 입력"이 전제입니다. Feature Spec Pack(SD-08)이 약하면 Day2의 구현·테스트 품질도 흔들립니다. 그래서 Day1의 마지막 한 시간은 새로운 것을 배우지 않고, 가진 것을 패킷으로 정리합니다.

ActivityWatch 목표 힌트 · S5 Spec Pack 점검

ActivityWatch의 활동 수집·요약·타임라인·카테고리 방향을 참고하되, 패킷에는 아래 세 층을 섞지 않고 표시합니다.

  • Core · Day2 구현: 기존 durationByApp·categorize·topApps·collectEvents 계약을 유지하고 sessionize만 test-first로 완성합니다.
  • Stretch · 선택 사항: 기본값은 none입니다. core와 gate가 GREEN이고 시간이 남을 때만 카테고리별 시간, 명시적 AFK 상태 필터, 하루 타임라인/날짜 필터, 합성 JSON import/export 중 0개 또는 1개를 별도 backlog로 남깁니다. Day2 완료 기준에는 넣지 않습니다.
  • Out · 이번 과정 제외: 실제 OS/browser watcher, 원본 창 제목·URL, DB·서버·전체 Web UI, REST API·query 호환.

일관성 질문: S1~S4가 모두 같은 { app, start, end } 입력, idleGapMs의 >/== 경계, [{ start, end, count }] 출력을 말하나요? 각 AC에 테스트 이름이 있고, 원본 창 제목·URL이 fixture나 출력에 없나요?

S5 원칙: 여기서는 새 기능을 추가하지 않습니다. 앞 단계에 없던 아이디어는 unknown 또는 stretch backlog로 보내고, Day2 core 계약만 하나로 묶습니다.

실습에서 기대하는 바와 결과 예시

기대하는 바

  • S1~S4 산출물을 새 요구 추가 없이 하나의 spec.md로 연결한다.
  • core·stretch·out을 분리하고 must-have AC에 테스트 이름을 연결한다.
  • 받는 사람이 설명 없이 Day2를 시작할 수 있는지 자가 판정한다.
