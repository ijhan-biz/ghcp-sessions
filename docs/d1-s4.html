Plan Mode 실습 — 계획과 실행을 분리한다

코드를 바로 만들게 하지 않고 "계획만 먼저" 받습니다. 단계별 stop point, Test Matrix, risk tier, rollback note를 구현 전에 합의해 복잡한 작업의 통제력을 확보합니다.

CF-04 Plan ModeGN-05 구현 계획SD-05 Test MatrixSD-11 Human GateHE-10 Rollback path
검증 목표 연결: 대상 P-A 개발자 · P-B 리드(검증 가능성) · 체인 단계 Plan·Test Matrix·rollback · 증거 Plan 기록·Test Matrix·rollback note 초안. 기준: 결과물 검증 기준

학습 목표

  • 요구사항 → 계획 → 실행을 분리하고, 각 단계에 stop point를 둔다.
  • AC를 Test Matrix로 펼치고(SD-05), 위험도(risk tier)와 Human Gate를 표시한다.
  • 되돌릴 경로(rollback note)를 구현 전에 초안으로 만든다.

미니강의 — 왜 계획을 먼저 받는가

에이전트는 한 번에 많은 것을 바꾸려 합니다. Plan Mode(CF-04)는 코드 작성 이전에 "무엇을, 어느 파일에서, 어떤 순서로, 무엇으로 검증하는가"를 합의합니다. 계획을 보고 잘못된 가정·과한 범위를 싸게 잡아낼 수 있습니다.

요구사항(AC)→계획(단계+stop point)→Test Matrix→risk/gate→단계별 실행
Plan Mode의 "단계별 실행 + stop point"는 Day2의 Loop(CF-06 Plan→Generate→Evaluate→Fix→Gate)로 자연스럽게 확장됩니다.

실습 — 계획부터 단계 실행까지

STEP 1 · 계획만 요청
[작업] 아래 기능 스펙(+AC)을 보고 구현 계획만 세워라. 코드 작성 금지.
[출력]
1. 변경 목표
2. 변경 파일 후보와 근거 (Context Manifest 참고)
3. 단계별 plan, 각 단계의 stop point
4. Test Matrix (AC ↔ 테스트)
5. risk tier와 Human Gate
6. rollback note 초안
[제약] 외부 패키지 추가 금지, public API 변경 금지, 실제 고객 데이터 금지.
STEP 2 · 계획 검토·수정 → 2~3단계로 합의

계획이 4단계를 넘으면 범위가 큰 신호입니다. 2~4단계로 줄이고 각 단계에 stop point가 있는지 확인합니다.

중간 브레이크(2분): 100분 세션의 절반 지점입니다. STEP 2까지가 컷라인(계획 + Test Matrix) — 여기까지면 최소 통과입니다. 잠깐 스트레치 후 STEP 3(실행)으로 갑니다. 시간이 부족하면 STEP 3~4는 Day2로 이월합니다.
STEP 3 · 한 단계만 실행 후 멈춤
"1단계만 구현. 끝나면 멈추고 변경 요약 + 테스트 결과 보고."

단계마다 검증 후 다음 단계로. 이 "멈춤" 습관이 Day2 게이트의 토대입니다.

참조 심화 — Definition of Done · 의사결정 가역성 (출처: 031 Playbook)

Definition of Done(031): 계획의 각 단계는 Code + Test + Required Check + Doc + Rollback Path 5개가 모두 있어야 "완료"로 봅니다. Plan에 이 5개 칸을 미리 넣어 두면 누락이 사라집니다.
one-way / two-way door(031): 되돌리기 쉬운 two-way door(코드 초안 등)는 AI 초안으로 빠르게, 되돌리기 어려운 one-way door(아키텍처·데이터·계약·릴리스)는 사람 결정으로. risk tier를 이 기준으로 나눕니다. 2개 이상 옵션을 비교하는 ADR-lite(옵션·가역성·리스크·owner)로 기록합니다.

체크포인트 & 산출물

산출물: Plan 실행 기록(계획 → 단계별 결과), Test Matrix, risk tier + Human Gate 표시, rollback note 초안.
  • 계획이 2~4단계로 제한되고 각 단계에 stop point가 있는가?
  • Test Matrix가 AC와 1:1로 연결되는가?
  • 승인이 필요한 작업(Human Gate)과 로컬에서 끝낼 작업이 구분되었는가?
컷라인: 시간 부족 시 STEP 1~2(계획+Test Matrix)까지만. 실제 코드 실행은 Day2로 이월 가능.

흔한 실수 & 공유 포인트

  • 계획 받자마자 전 단계 일괄 실행 → 통제력 상실. 반드시 한 단계씩.
  • rollback note를 "나중에" → 구현 전에 초안이라도 만들어야 실패 시 빠릅니다.
공유 포인트: "계획 단계에서 잡아낸 잘못된 가정" 한 줄. 계획-실행 분리의 가치를 가장 잘 보여주는 사례입니다.
