Day1 복습 & 환경 재점검 — 그대로 실행 가능한 상태인가

Day1의 Feature Spec Pack을 다시 로딩하고, 환경 점검 스크립트를 다시 실행해 정상인지 확인하며, baseline이 여전히 통과하는지 확인합니다. 오늘 구현할 must-have AC만 표시해 범위를 좁힙니다.

OR-16 Handoff환경 점검(setup)OR-15 로컬 브랜치

학습 목표

  • Day1 산출물을 입력으로 다시 불러오고, 환경이 어제와 동일한지 확인한다.
  • 오늘 구현할 must-have AC를 1~3개로 좁힌다.
  • 변경 전 git diff가 비어 있거나 의도된 상태인지 확인한다(clean branch).

미니강의 — Day2는 "안전한 실행"의 날

Day1이 좋은 입력을 만들었다면 Day2는 그것을 로컬 개발 루프로 실행합니다. 핵심은 ① 권한을 좁히고, ② 로그를 남기고, ③ 역할을 나누며, ④ 게이트를 통과해야 다음으로 간다는 구조입니다. 그래서 첫 30분은 "어제 만든 계획이 그대로 실행 가능한가"를 확인하는 데 씁니다.

실습 — 재개 체크

STEP 1 · 브랜치/환경 확인
git status
git branch --show-current      # lab/copilot-workbook 인지
git diff --stat                # 비어있거나 의도된 변경인지
npm test                       # baseline 다시 통과? 실패면 원인 먼저 기록
STEP 2 · Feature Spec Pack 로딩 & must-have 표시

YELLOW였던 참가자는 여기서 10분 보강합니다(빠진 AC/Test Matrix 채우기). RED는 sample-project-web-curation/ 폴백 스펙으로 전환합니다(FEATURE-SPEC.md 채택 → BACKLOG에서 slice 선택).

오늘 구현할 must-have AC:
[ ] AC1 ...
[ ] AC2 ...
(나머지는 nice-to-have로 분리)

체크포인트 & 산출물

산출물: 재개 체크 결과, clean branch, 오늘의 must-have AC 목록.
  • baseline이 통과하는가(혹은 실패 원인이 기록되었는가)?
  • 오늘 범위가 must-have 1~3개로 좁혀졌는가?
컷라인: Spec Pack이 RED면 즉시 sample-project-web-curation/ 폴백으로 전환 — 환경/스펙 복구에 30분을 다 쓰지 않습니다.
