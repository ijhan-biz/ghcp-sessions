Day1 복습 & 환경 재점검 — 그대로 실행 가능한 상태인가

Day1의 Feature Spec Pack을 다시 로딩하고, 환경 점검 스크립트를 다시 실행해 정상인지 확인하며, baseline이 여전히 통과하는지 확인합니다. 오늘 구현할 must-have AC만 표시해 범위를 좁힙니다.

Agentic SDLC 지도OR-16 Handoff환경 점검(setup)OR-15 로컬 브랜치

학습 목표

  • Agentic SDLC 지도 위에서 오늘(Day2)이 어느 단계를 다루는지 위치를 잡는다.
  • Day1 산출물을 입력으로 다시 불러오고, 환경이 어제와 동일한지 확인한다.
  • 오늘 구현할 must-have AC를 1~3개로 좁힌다.
  • 변경 전 git diff가 비어 있거나 의도된 상태인지 확인한다(clean branch).

미니강의 — Agentic SDLC 지도로 "오늘 위치" 잡기

시간 배분(30분): 이 지도는 약 5분 동안 "오늘 어디를 하는지"만 훑습니다 — 아래 두 표는 참조용이라 외우지 않습니다. 나머지 25분은 복습·환경 재점검(아래 실습)과 must-have AC 좁히기에 씁니다. Spec Pack이 RED면 설명을 접고 즉시 sample-project-web-curation/ 폴백으로 넘어갑니다.

Day1이 좋은 입력(의도·명세·설계)을 만들었다면, Day2는 그것을 안전하게 실행(구현·검증·배포·운영)하는 날입니다. 전체를 한 장의 지도로 보면 각 세션이 어디에 앉는지 분명해집니다. 핵심은 단계마다 권한을 좁히고 · 로그를 남기고 · 게이트를 통과해야 다음으로 간다는 폐루프 구조입니다.

Intent 분석→ 명세(Spec)→ 구현→ 검증·테스트→ 배포→ 모니터·피드백↺ Spec 갱신

화살표 지점마다 권한 제약·정책 주입·검증 게이트(하네스)가 붙어 에이전트의 자율 실행을 통제합니다.

Day2 실습 프로젝트 — VS Code 새 창에서 열기

Day2의 구현 실습은 독립 프로젝트 sample-project-web-curation(검색결과 큐레이션 엔진)을 VS Code 새 창에 열어 진행합니다. 강의 문서와 분리된 깨끗한 프로젝트 워크스페이스여야 Copilot(특히 Agent 모드)의 파일·도구 범위가 이 프로젝트로 좁혀집니다. (본인 기능 코드가 있으면 그 폴더를 같은 방식으로 엽니다.)

① 새 창에 프로젝트 열기

방법 A · 메뉴

File → New Window(⌘⇧N / Ctrl+Shift+N) → File → Open Folder… → sample-project-web-curation 폴더 선택.

방법 B · 터미널(code CLI)
# -n = 새 창으로 열기 (code 명령이 설치돼 있어야 함)
code -n sample-project-web-curation

② 실행에 필요한 파일

sample-project-web-curation 구성 파일 · 용도
파일용도

③ 어떻게 실행하나

새 창의 통합 터미널에서 (Terminal → New Terminal)
node -v              # v18 이상인지 확인
npm test             # baseline: 4 pass, 2 skip(정상)

# D2·S4 test-first 루프:
#  1) test/curate.test.js 의 { skip: true } 제거 → npm test (실패=레드 확인)
#  2) src/curate.js 의 normalizeUrl 구현        → npm test (통과=그린)

즉 skip을 켜 실패를 먼저 보고(레드) → 구현해서 통과(그린)가 Day2 test-first의 핵심 루프입니다. 전체 진행 순서는 프로젝트 README.md에 있습니다.

왜 새 창에서 여나: ① Copilot(특히 Agent 모드)의 파일·도구 범위가 이 프로젝트로 한정돼 안전하고, ② 강의 문서와 섞이지 않아 컨텍스트·git diff·커밋이 깔끔하며, ③ 워크스페이스 설정을 프로젝트 단위로 관리할 수 있습니다.
