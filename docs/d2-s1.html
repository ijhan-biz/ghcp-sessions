하네스 (1) 기초·CLI — 자연어 제약을 검증으로

하네스 엔지니어링의 개념(자연어 제약 → 실행 가능한 검증)을 세우고, Copilot CLI를 그냥 실행하지 않고 권한을 좁히고 로그를 남기는 습관을 만듭니다. 실행 로그를 해석하는 법까지 익힙니다.

학습 목표

  • 하네스 = "자연어 제약을 로컬에서 실행 가능한 검증/게이트로 바꾸는 작업"임을 이해한다(HE-01).
  • Copilot CLI에서 --allow-tool/--deny-tool/--log-dir/--output-format로 권한·로그·출력을 제어한다.
  • 실행 로그를 읽고 "무엇을 시도했고 왜 멈췄는가"를 해석한다.

미니강의 — 프롬프트 약속을 실행 밖으로 옮긴다

Day1에서 가드레일을 프롬프트에 적었습니다. 하지만 프롬프트 안의 약속은 모델이 어길 수 있습니다. 하네스는 그 약속을 실행 경로 바깥의 결정론적 검사(HE-06)로 옮깁니다. 오늘(S1)은 그 첫 단계로 CLI 권한과 로그를 다룹니다.

주의: Copilot CLI 옵션은 preview/조직 정책에 따라 다를 수 있습니다. 실습 시작 시 gh copilot -- --help 출력을 현재 환경의 기준으로 삼습니다. CLI 불가 시 Copilot Chat(CF-01)으로 fallback하고 강사 데모 로그를 분석합니다.

실습 — 권한을 좁힌 CLI 실행

STEP 1 · 기본 확인
gh auth status
gh copilot -- --help
STEP 2 · 권한·로그를 좁힌 실행
gh copilot -- -p "현재 브랜치 변경 파일과 테스트 명령 후보를 요약" \
  --allow-tool 'shell(git)' \
  --deny-tool  'shell(rm)' \
  --log-dir    .copilot-harness/logs \
  --output-format json

--allow-tool로 허용 도구를 좁히고, --deny-tool로 위험 명령을 막고, --log-dir로 기록을 남깁니다. json 출력은 이후 자동화 연계용입니다.

STEP 3 · 로그 해석
[작업] 아래 Copilot CLI 실행 로그를 보고 요약해라.
[출력] 실행 의도 · 사용 도구 · 차단된 작업 · 다음에 필요한 권한 · 위험 신호.

체크포인트 & 산출물

산출물: 권한 플래그가 적용된 CLI 실행 로그(.copilot-harness/logs) + 로그 해석 메모.
  • --allow-tool로 도구가 좁혀졌는가?
  • --deny-tool로 위험 명령이 명시적으로 막혔는가?
  • 로그에서 "무엇을 했고 왜 멈췄는가"를 한 문장으로 말할 수 있는가?
컷라인: CLI 미설치자는 강사 데모 로그 분석으로 대체. 개념(권한 최소화·로깅)만 잡으면 통과입니다.

참조 심화 — CLI 하네스 플래그 · 차단 패턴

권한·로그 플래그 모음

Copilot CLI 권한·로그 플래그
플래그용도
-p/--prompt · -i/--interactive1회 요청 / 대화형
--allow-tool · --deny-tool도구 allow/deny
--allow-url · --deny-url웹 접근 경계
--add-dir · --allow-all-paths경로 범위 제어
--log-dir · --log-level로그 경로/레벨
--output-format json · --available-tools구조화 출력 / 도구 인벤토리

차단 권장 명령 패턴

rm -rf · git push --force · kubectl delete · terraform apply · git rebase -i — 위험도에 따라 warn 또는 block.

핵심 원칙: "프롬프트만으로는 안전하지 않다 — 정책은 실행 경계에 붙인다." 실행 전(pre-check)과 후(post-check)를 모두 검사하고, 처음 1~2주는 log-only로 오탐을 관찰한 뒤 차단으로 승격합니다(logging-first).

흔한 실수 & 공유 포인트

  • 권한 제한 없이 CLI 실행 → 에이전트가 무엇이든 할 수 있는 상태. 항상 allow/deny로 좁힙니다.
  • 프롬프트에 모델명을 적고 "그 모델로 돈다"고 가정 → 보장되지 않습니다(CF-10, S2에서 자세히).
공유 포인트: "deny-tool로 막은 위험 명령" 사례. 팀 보안 관점에서 바로 쓸 수 있는 공유 거리입니다.
