미니강의 ① — 로컬 게이트: 약속을 코드로

GitHub PR/Actions가 없는 환경에서 동일한 품질 게이트를 로컬에 둡니다(HE-03). wrapper는 권한·로그·출력 형식을 고정하고 위험 명령을 차단하며, policy-check는 금지 파일 변경·secret·외부 패키지 추가를 결정론적으로 감지합니다.

교육용 wrapper (발췌)
#!/usr/bin/env zsh
set -euo pipefail
prompt="$*"
mkdir -p .copilot-harness/logs
exec gh copilot -- -p "$prompt" \
  --allow-tool 'shell(git)' --allow-tool 'shell(npm test)' \
  --deny-tool  'shell(rm)'  --deny-tool  'shell(git push --force)' \
  --log-dir .copilot-harness/logs --output-format json
교육용 policy-check (발췌)
// scripts/policy-check.mjs
import { execSync } from 'node:child_process';
const changed = execSync('git diff --name-only',{encoding:'utf8'}).split('\n').filter(Boolean);
const blocked = [/^\.env$/,/^\.env\./,/^secrets\//,/^prod\//];
const hits = changed.filter(f => blocked.some(p => p.test(f)));
if (hits.length){ console.error('Blocked files changed:\n'+hits.join('\n')); process.exit(1); }
console.log('policy-check passed');
로컬 게이트 실행
npm run lint && npm test && node scripts/policy-check.mjs
운영 팁(HE-13 logging-first): 처음엔 경고만 남기고 위반을 관찰한 뒤, 오탐을 줄이고 위험도가 높은 항목부터 block으로 승격합니다.

실습 — 게이트 + Canvas 작성

  1. wrapper와 policy-check를 샘플 레포에 추가하고 로컬 게이트를 1회 실행한다(HE-03).
  2. Agent Team Canvas에 5개 역할을 본인 기능팀 인물/역할로 매핑한다.
  3. Fleet 설계표와 Loop Canvas를 본인 기능 1건 기준으로 채운다(중단 조건 필수).
산출물: Agent Team Canvas + Fleet 설계표 + Loop Canvas + 동작하는 로컬 게이트(최소 policy-check 1개).
컷라인(최소 완료 경로 EV-10): 80분이 빠듯하면 동작하는 policy-check 1개 + Loop Canvas의 '중단 조건' 1줄이면 통과입니다. Fleet 설계표·Agent Team 매핑은 초안이면 충분하고, wrapper·역할 상세는 참조로 이어갑니다. (개념이 많은 세션이므로 "동작하는 게이트 하나"를 우선합니다.)
Hard gate: approval_id 없는 write/destructive/prod/customer-data 작업은 block · rollback owner 없는 운영 변경은 block · 검증 기준 없는 Evaluator 판정은 revise.
사전 게이트 vs 사후 게이트: approval_id·destructive는 실행 전 차단(preventive)이 되지만, customer-data 변경 같은 항목은 diff가 나온 실행 후 감지(detective) → 즉시 rollback 트리거로 다룹니다. 모든 게이트가 사전 차단 가능한 것은 아닙니다.

도입 로드맵 G0→G4

G0 읽기전용 파일럿→G1 PR-first(Evaluator)→G2 Harness-gated→G3 Human-gated(approval_id)→G4 SLO 운영
발행 하드게이트: 결함/주장 비율 CD_ratio > 0.35 = 발행 block. Harness PASS는 구조 검증이지 사실 검증이 아니다 — 사실/보안/배포 승인은 사람이 합니다.

흔한 실수 & 공유 포인트

  • Loop에 중단 조건이 없음 → 무한 반복·비용 폭증. max retry·stop condition을 반드시 넣습니다.
  • Evaluator가 "좋아 보임"으로 통과 → 기준 없는 판정. AC·테스트에 근거해 pass/revise/block.
  • 모든 단계에 고비용 모델 고정 → 비용 낭비. 역할별 라우팅으로 분리합니다.
공유 포인트: "내 기능팀 역할 ↔ Agent Teams 매핑"은 팀이 바로 따라 할 수 있는 강력한 공유 자산입니다.
