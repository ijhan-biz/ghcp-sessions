SDD (2) — 통합 & 유닛테스트 · 리뷰 패킷

기능을 통합 관점에서 점검하고 유닛테스트를 보강한 뒤, "동작한다"가 아니라 증거와 되돌림 경로가 있는 상태로 마무리합니다. PR을 대신하는 local review packet을 제출물로 만듭니다.

HE-03 로컬 게이트HE-18 Evidence bundleHE-15 Local review packetHE-10 Rollback pathHE-16 No-cloud attestation

학습 목표

  • 유닛테스트를 보강하고 통합 관점(주변 영향)을 점검한다.
  • evidence bundle(변경 요약·테스트·정책체크·diff·리스크)을 만든다(HE-18).
  • rollback note와 no-cloud attestation을 포함한 local review packet을 제출한다(HE-15).

미니강의 — PR 없이도 "리뷰 가능한 상태"를 만든다

GitHub PR이 없는 환경에서 리뷰어가 볼 수 있도록 제출물을 패킷으로 묶습니다(HE-15). 패킷은 spec.md·diff·test log·정책/수동 게이트 결과·rollback note·no-cloud attestation으로 구성됩니다. 이것이 Day2의 핵심 산출물이자 수료 필수 항목(EV-09)입니다.

실습 — 검증 → 패킷

STEP 1 · 검증 명령
npm test
node scripts/policy-check.mjs
git diff --stat
git diff -- src tests
STEP 2 · Evidence Bundle (HE-18)
  • 변경 요약: 어떤 AC를 위해 어떤 파일을 바꿨는가
  • 테스트 결과: 실행 명령·통과/실패·실패 원인
  • 정책 체크 결과: 금지 파일/secret/외부 패키지 여부
  • 리스크: 남은 known gap, manual check 필요 여부
STEP 3 · Rollback Note (HE-10·HE-11)
## Rollback Note
- Trigger: AC 회귀 / 테스트 실패 / 금지 파일 변경 감지
- Owner: [담당자/PL]
- Action: git restore [files] 또는 해당 local commit revert
- Verify: npm test && node scripts/policy-check.mjs
- Completion: baseline green, 스펙 v1 상태로 복구
STEP 4 · Local Review Packet 묶기

spec.md + diff + test log + 게이트 결과 + rollback note + no-cloud attestation(HE-16: Codespaces·PR·Actions 미사용 선언)을 한 폴더로.

STEP 5 · P-B(리드/PL) 승인 게이트

PR이 없으므로 승인 신호를 명시적으로 남깁니다: 패킷을 공유 폴더/Git tag로 전달 → 리드가 approve(커밋 메시지나 APPROVALS.log에 승인자·일시 기록) · request-changes(.review/feedback.md에 사유·개선 방향) · block(사유 + 에스컬레이션). 승인 기록이 없는 변경은 '리뷰 완료'로 보지 않습니다.

체크포인트 & 산출물

산출물: 유닛테스트 포함 변경 세트(로컬 커밋) + local review packet(evidence bundle·rollback note·no-cloud attestation 포함).
리뷰 패킷 go/no-go 기준
패킷 항목gono-go
구현테스트 통과·diff 설명 가능테스트 실패 또는 diff 설명 불가
게이트test/policy-check 실행됨게이트 없음
rollback되돌림 명령·owner 명시없음
컷라인: 테스트 1개 통과 + policy-check 1회 + rollback note 1개 = 최소 수료 경로(EV-10).

롤백 드릴 리허설 (033)

release-readiness 진입 시 dry-run으로 MTTR·owner·신호(metric)를 기록합니다. 되돌림을 "처음" 해보는 일이 없게 합니다.

발행 게이트 hold(033): runbook·승인·지표 중 하나라도 없으면 내부 데모용으로만. CD_ratio > 0.35(결함/주장 비율)이면 발행 block.

흔한 실수 & 공유 포인트

  • "테스트 통과"로 끝냄 → 증거·롤백이 없으면 리뷰 불가. 패킷까지 만듭니다.
  • rollback note를 형식적으로 → 실제 명령과 owner가 있어야 의미가 있습니다.
공유 포인트: "게이트가 잡아낸 위반 1건"과 "되돌림에 걸린 시간". 검증 문화의 효과를 수치로 공유하면 설득력이 큽니다.
