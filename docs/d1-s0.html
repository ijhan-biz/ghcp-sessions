OT & 로컬 환경 점검 — 돌아갈 baseline부터 만든다

2일 전체 흐름과 "이 과정의 약속"을 공유하고, 실습 내내 의지할 로컬 환경을 smoke test로 검증한 뒤, 문제가 생겨도 되돌아올 수 있는 baseline 브랜치를 만듭니다.

관련: EN-01 Dev ContainerEN-14 Smoke testEN-18 Green/Yellow/RedHE-14 Local-onlyEN-15 Fallback

학습 목표

  • 2일 과정의 산출물 줄기(기능 스펙 → … → Custom Skill → 공유)를 이해하고, 본인 기능 스펙 후보 1건을 정한다.
  • VS Code · Copilot · Docker · Dev Container · Git · npm을 smoke test로 점검하고 Green/Yellow/Red를 자가 판정한다(EN-18).
  • 실습 브랜치와 baseline 테스트 결과를 남겨 되돌아올 지점을 확보한다.

미니강의 — 왜 환경 점검부터 하는가

이 과정은 로컬 전용(local-only, HE-14)입니다. Codespaces·GitHub PR/Actions를 쓰지 않고 개인 PC의 VS Code·Git·Dev Container에서 모든 실습을 합니다. 따라서 첫 시간에 환경이 흔들리면 이틀 내내 흔들립니다.

Local-only의 정확한 뜻: 코드 실행·테스트·검증·제출물은 로컬에서 만든다는 의미입니다. Copilot에 보내는 질의 자체는 조직 정책에 따라 서비스로 전송될 수 있으므로, 고객정보·키/토큰·반출 금지 로그는 입력하지 않습니다(OR-12 데이터 경계 · OR-13 민감정보).

Dev Container를 쓰는 이유 (EN-01)

참가자 PC마다 Node 버전·OS·전역 패키지가 달라 "제 PC에선 되는데요"가 반복됩니다. .devcontainer/devcontainer.json으로 정의한 컨테이너에서 열면 모두 같은 환경이 됩니다. Docker가 불가하면 Host Node fallback(EN-16)으로 진행합니다 — 테스트는 되지만 환경 편차가 늘어납니다.

실습 — Smoke test & baseline

STEP 1 · 도구 점검

터미널에서 아래를 실행해 버전이 출력되는지 확인합니다(EN-14).

code --version
git --version
gh --version && gh auth status
docker version          # Docker 불가 시 Host Node fallback
node -v && npm -v
STEP 2 · 샘플 열고 컨테이너 재기동

샘플 레포를 로컬 clone(또는 강사 제공 폴더)한 뒤 VS Code에서 "Reopen in Container"를 시도합니다. 실패하면 로컬 런타임으로 진행합니다.

# 예: 토큰 실험 샘플(EN-13) 또는 SDD 샘플(EN-12)
git clone <sample-repo-url> && cd <sample>
# VS Code: Command Palette → Dev Containers: Reopen in Container
npm install
STEP 3 · baseline 테스트 & 실습 브랜치

지금 통과하는 상태를 기록해 둬야 나중에 "내가 깬 건지 원래 그런지" 알 수 있습니다.

npm test                          # baseline 결과를 메모
git checkout -b lab/copilot-workbook   # 로컬 전용 브랜치 (OR-15)
git status
STEP 4 · Copilot 동작 확인

Copilot Chat(CF-01)에 한 줄 질의해 응답이 오는지, Inline 제안(CF-11)이 뜨는지 확인합니다. Chat은 CLI 불가 시 1차 fallback 경로입니다.

흔한 실수

  • Docker 데몬 미실행 상태로 Reopen → 먼저 Docker Desktop을 켭니다.
  • baseline을 안 남기고 바로 코드 변경 → 회귀 판단 불가. 반드시 STEP 3을 먼저.
  • main에서 바로 실습 → 항상 lab/* 브랜치에서.

공유 포인트 (D2·S7로 연결)

오늘의 환경 상태(Green/Yellow/Red)와 막힌 지점을 한 줄로 기록하세요. 마지막 날 "환경 셋업에서 무엇이 어려웠고 어떻게 풀었는가"는 동료에게 가장 도움이 되는 공유 주제입니다.
