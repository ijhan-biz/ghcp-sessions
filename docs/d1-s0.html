OT & 로컬 환경 점검 — 돌아갈 baseline부터 만든다

2일 전체 흐름과 "이 과정의 약속"을 공유하고, 실습 내내 의지할 로컬 환경을 smoke test로 검증한 뒤, 문제가 생겨도 되돌아올 수 있는 baseline 브랜치를 만듭니다.

관련: 환경 점검·교정 스크립트(setup)EN-14 Smoke testEN-18 Green/Yellow/RedHE-14 Local-onlyEN-15 Fallback

학습 목표

  • 2일 과정의 산출물 줄기(기능 스펙 → … → Custom Skill → 공유)를 이해하고, 본인 기능 스펙 후보 1건을 정한다.
  • VS Code · Copilot · Git · Node · gh 를 환경 점검·교정 스크립트로 점검·자동 교정하고 Green/Yellow/Red를 자가 판정한다(EN-18).
  • 실습 브랜치와 baseline 테스트 결과를 남겨 되돌아올 지점을 확보한다.

미니강의 — 왜 환경 점검부터 하는가

이 과정은 로컬 전용(local-only, HE-14)입니다. Codespaces·GitHub PR/Actions를 쓰지 않고 개인 PC의 VS Code·Git·Node에서 모든 실습을 합니다. 따라서 첫 시간에 환경이 흔들리면 이틀 내내 흔들립니다.

Local-only의 정확한 뜻: 코드 실행·테스트·검증·제출물은 로컬에서 만든다는 의미입니다. Copilot에 보내는 질의 자체는 조직 정책에 따라 서비스로 전송될 수 있으므로, 고객정보·키/토큰·반출 금지 로그는 입력하지 않습니다(OR-12 데이터 경계 · OR-13 민감정보).

환경 점검·교정 스크립트 (Dev Container 없이)

참가자 PC마다 Node 버전·OS·전역 패키지가 달라 "제 PC에선 되는데요"가 반복됩니다. 이 과정은 컨테이너(Docker) 대신 현재 터미널의 환경을 직접 점검·교정하는 스크립트를 씁니다. setup-mac.sh(macOS) / setup-windows.bat(Windows)가 Node·git·gh·VS Code 확장을 확인하고, 누락/구버전(Node 18+ 미만)을 자동 설치·업그레이드한 뒤 labs 테스트로 준비 완료까지 확인합니다. 별도 컨테이너·Docker가 필요 없습니다.

실습 — Smoke test & baseline

STEP 1 · 도구 점검

터미널에서 아래를 실행해 버전이 출력되는지 확인합니다(EN-14).

code --version
git --version
gh --version && gh auth status
node -v && npm -v
STEP 2 · 환경 점검·교정 스크립트 실행

컨테이너 없이, 현재 터미널에서 환경 점검·교정 스크립트를 실행합니다. 누락 도구·구버전 Node를 자동으로 바로잡습니다.

# macOS
bash setup-mac.sh           # 점검 + 자동 교정
# Windows (명령 프롬프트)
setup-windows.bat           # 점검 + 자동 교정
# 교정 없이 점검만: --check
STEP 3 · baseline 테스트 & 실습 브랜치

지금 통과하는 상태를 기록해 둬야 나중에 "내가 깬 건지 원래 그런지" 알 수 있습니다.

npm test                          # baseline 결과를 메모
git checkout -b lab/copilot-workbook   # 로컬 전용 브랜치 (OR-15)
git status
STEP 4 · Copilot 동작 확인

Copilot Chat(CF-01)에 한 줄 질의해 응답이 오는지, Inline 제안(CF-11)이 뜨는지 확인합니다. Chat은 CLI 불가 시 1차 fallback 경로입니다.

VS Code Copilot 기능 전체 지도: 환경이 준비됐으면, VS Code에서 쓸 수 있는 Copilot 기능(채팅 표면 · Agent/Plan/Ask · 자동완성 · 컨텍스트 · 도구/MCP · 커스터마이징 등)을 VS Code Copilot 기능 가이드에서 한눈에 확인하세요.

실습 예제 시나리오 — 결제(부가세) 기능

본인 기능이 없거나 감을 먼저 잡기 위해, 이 과정은 공통 설명 예제로 결제 금액의 부가가치세(VAT) 계산 기능(calcVat())을 씁니다. Day1의 프롬프트·AC 설명이 이 도메인 위에서 이어집니다. 다만 Day2의 구현 실습은 본인 기능(없으면 폴백 sample-project-web-curation)을 VS Code 새 창에 열어 진행합니다(D2·S0).

결제(부가세) 예제 — 무엇 · 규칙 · 언제 쓰나
구분내용
무슨 기능주문/청구 금액에 대해 부가세를 계산하는 순수 함수 calcVat(금액, 옵션).
규칙(도메인)일반 품목 VAT 10% · 면세 품목(도서·일부 식품 등) VAT 0% · 음수 금액은 오류(방어).
언제 쓰나(실무)이커머스 장바구니 결제, 구독 청구서, POS 영수증, 정산 배치 — 최종 청구액을 확정할 때 세금을 계산. 예: 장바구니 합계 = 상품가 + calcVat(상품가).
왜 예제로 좋나규칙이 명확해 AC(정상 10%·예외 음수·경계 면세 0)가 자연스럽고, 순수 함수라 로컬 테스트가 쉬우며, "세금 오류 = 돈·신뢰 문제"라 회귀 리스크가 실감납니다.
두 가지 역할 구분: ① 설명 예제 = 결제(calcVat) — 강의가 기법을 보여줄 때 쓰는 공통 예입니다(실제 결제·PG·DB 없이 계산 로직만, 비식별·로컬). ② 실습 프로젝트 = 본인 기능, 없으면 폴백 sample-project-web-curation(검색결과 큐레이션) — Day2에서 새 창으로 열어 직접 구현합니다.
