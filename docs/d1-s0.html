미니강의 — 왜 환경 점검부터 하는가

이 과정은 로컬 전용(local-only, HE-14)입니다. Codespaces·GitHub PR/Actions를 쓰지 않고 개인 PC의 VS Code·Git·Node에서 모든 실습을 합니다. 따라서 첫 시간에 환경이 흔들리면 이틀 내내 흔들립니다.

Local-only의 정확한 뜻: 코드 실행·테스트·검증·제출물은 로컬에서 만든다는 의미입니다. Copilot에 보내는 질의 자체는 조직 정책에 따라 서비스로 전송될 수 있으므로, 고객정보·키/토큰·반출 금지 로그는 입력하지 않습니다(OR-12 데이터 경계 · OR-13 민감정보).

환경 점검·교정 스크립트 (Dev Container 없이)

참가자 PC마다 Node 버전·OS·전역 패키지가 달라 "제 PC에선 되는데요"가 반복됩니다. 이 과정은 현재 터미널의 환경을 직접 점검합니다. setup-mac.sh/setup-windows.bat는 Node·git·VS Code를 확인하고, labs 10/2와 activity-log 5/2를 모두 smoke-test해야 READY로 판정합니다.

실습 예제 시나리오 — 결제(부가세) 기능

Day1 미니강의는 설명 예제로 결제 VAT 계산(calcVat())을 씁니다. 그러나 학생이 직접 작성하고 16개 checkpoint로 검증받는 산출물은 전원 공통 sample-project-activity-log/sessionize입니다.

결제(부가세) 예제 — 무엇 · 규칙 · 언제 쓰나
구분내용
무슨 기능주문/청구 금액에 대해 부가세를 계산하는 순수 함수 calcVat(금액, 옵션).
규칙(도메인)일반 품목 VAT 10% · 면세 품목(도서·일부 식품 등) VAT 0% · 음수 금액은 오류(방어).
언제 쓰나(실무)이커머스 장바구니 결제, 구독 청구서, POS 영수증, 정산 배치 — 최종 청구액을 확정할 때 세금을 계산. 예: 장바구니 합계 = 상품가 + calcVat(상품가).
왜 예제로 좋나규칙이 명확해 AC(정상 10%·예외 음수·경계 면세 0)가 자연스럽고, 순수 함수라 로컬 테스트가 쉬우며, "세금 오류 = 돈·신뢰 문제"라 회귀 리스크가 실감납니다.
두 가지 역할 구분: ① 설명 데모 = labs/calcVat 10/2. ② 학습 checkpoint = 전원 공통 sample-project-activity-log 5/2에서 시작해 7/0까지 진행. 개인 프로젝트 적용은 공통 GREEN 후 또는 D+7입니다.

이 세션의 실행 코드 (Hands-on)

이 세션의 목표는 오늘 실습을 시작할 수 있는 로컬 baseline을 만드는 것입니다. 아래 세 명령으로 (1) 환경 준비도를 점검하고, (2) 통과 상태(baseline)를 기록하고, (3) 작업 브랜치를 팝니다.

두 baseline을 구분해 확인: setup readiness는 labs와 activity-log를 모두 보고, 학습 checkpoint는 activity-log의 5/2/0을 사용합니다.
cd labs

npm run lab -- doctor                  # 학습 baseline: 5/2/0
npm run lab -- check d1-s0
git checkout -b lab/copilot-workbook
