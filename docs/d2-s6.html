Skill 사용 및 커스터마이징 — 나만의 재사용 솔루션을 만든다

오늘 만든 프롬프트·제약·워크플로를 매번 새로 쓰지 않도록 Custom Skill / Custom Agent로 묶습니다. 이것이 이 과정의 결정체 — 에이전트로 동작하는 자신만의 솔루션입니다.

CF-08 Custom Skill/AgentPT-11 프롬프트 템플릿CF-05 FleetCF-10 Model routingEV-09 필수 수료

학습 목표

  • Skill(절차·지식 재사용)과 Custom Agent(역할·도구·모델까지 묶음)의 차이를 이해한다.
  • 본인 반복 업무를 목적·입력·절차·금지·출력 구조의 Custom Skill로 정형화한다(CF-08).
  • Fleet 안에서 역할별 Custom Agent와 모델 기준·도구 범위를 정한다.

미니강의 — Skill은 절차, Agent는 역할까지

Skill은 "이 반복 업무를 이렇게 한다"는 절차·지식을 MD로 재사용하는 단위입니다. Custom Agent는 거기에 역할·노출 도구·모델 기준까지 묶습니다. D2·S3에서 설계한 본인 워크플로를 여기서 자산으로 굳힙니다.

설계 질문: 어떤 반복 업무를 줄이나? 입력은? 절대 하면 안 되는 일은? 완료 산출물과 pass/revise/block 기준은? Fleet에서 어떤 역할인가? 노출/비노출 도구는?

실습 1 — Custom Skill 작성 (CF-08)

예: 기능 스펙 SDD 보조 Skill
# 기능 스펙 SDD 보조 Skill
## 목적
비식별 기능 스펙을 User Story·AC·Test Matrix·구현 계획으로 정리한다.
## 입력
- Feature Spec Pack / Context Manifest / 현재 테스트 결과
## 절차
1. 민감정보/고객 데이터 확인  2. User Story·AC를 SMART하게
3. allowed/blocked 분리  4. test-first 계획  5. human gate 표시
## 금지
- 고객명/계정/secret 추정 · 외부 패키지 추가 제안 · 승인 없는 운영/배포/삭제
## 출력
- AC 표 · Context Manifest · Test Matrix · Plan · Risk/Gate · Rollback Note

참조 심화 — 모델 라우팅 & 관측성

모델 지정 2가지 경로

모델 라우팅 2경로 (CF-10)
경로방법성격
Custom Agent 고정YAML frontmatter model: ...역할 고정(표준 역할 권장)
Fleet 런타임 라우팅SDK/API · model picker · handoff 필드호출 시 동적
프롬프트 모델명본문에 "~모델로"비공식 힌트(보장 아님)

단계별 모델 계층(토큰 효율)

계획=고추론→구현=빠른/auto→리뷰=auto/중간

고추론 모델은 의사결정 병목에만 씁니다. 구현 단계가 합의된 계획을 다시 의심하면 토큰이 폭증합니다.

핵심 원칙: 표준 에이전트엔 model:을 명시해 UI 기본값 누수를 막고, UI model picker 표시와 실제 호출 모델이 다를 수 있으니 세션 로그로 확인합니다(~/.copilot/session-state/<id>/events.jsonl). 안 쓰는 MCP/도구는 컨텍스트·비용을 늘리므로 tools:로 좁힙니다.
관측성: 토큰 단위 상세는 OpenTelemetry gen_ai.usage.*(input/output/reasoning tokens), 비용 원장은 Billing/Usage API(집계, 토큰 단위 아님). hook(preToolUse/postToolUse)은 정책·감사용이지 토큰 집계용이 아니며, 토큰/secret을 로그에 남기지 않습니다.

체크포인트 & 산출물 (수료 필수)

산출물: 본인 업무용 Custom Skill 1개(목적·입력·절차·금지·출력) + Custom Agent/Fleet 운영 기준. 이는 수료 필수 항목입니다(EV-09).
  • Skill에 입력·절차·금지·출력이 모두 있는가?
  • 팀의 반복 업무에 바로 재사용 가능한가(추상적 지침이 아니라)?
  • Fleet 역할별 도구/중단 조건이 분리되었는가?
여기까지 오면: 여러분은 "Copilot에게 코드를 맡기는" 단계를 넘어, 에이전트로 동작하는 자신만의 솔루션을 손에 쥔 것입니다. 다음 세션은 이걸 팀에 나누는 시간입니다.

흔한 실수 & 공유 포인트

  • 추상적 지침만 적음 → 재사용 불가. 입력/출력/금지를 구체적으로.
  • 모든 도구를 노출 → 보안·컨텍스트 낭비. 필요한 도구만.
공유 포인트: S7에서 이 Skill을 30초 시연할 수 있게 입력 1개와 기대 출력 1개를 준비하세요.
