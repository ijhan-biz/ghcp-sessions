하네스 (3) — 본인 기능팀 워크플로 설계

앞 세션의 도구(게이트·Agent Teams·Fleet·Loop)를 내 반복 업무에 적용합니다. 자연어 제약을 테스트/체크로 코드화하고, 자동화 포인트를 골라 나만의 하네스 워크플로를 설계합니다.

  • 자연어 제약 → 테스트/체크/정책으로 코드화 포인트를 식별한다.

미니강의 — 여기서 "자신만의 솔루션"이 시작된다

지금까지는 주어진 예제로 도구를 익혔습니다. 이 세션부터는 내 업무를 재료로 씁니다. "매번 똑같이 하는 일"을 하나 골라 하네스로 감싸면, 그것이 곧 팀에 남길 나만의 솔루션의 씨앗입니다. 이 설계는 D2·S6에서 Custom Skill/Agent로 결정화됩니다.

경계(SD-11): AI에 맡길 일(요약·테스트 후보·diff 요약)과 사람이 승인할 일(scope freeze·보안 go/no-go·배포)을 분리합니다. 장기 실행은 timebox·max retry·kill switch(HE-09)를 둡니다.

실습 — 본인 워크플로 캔버스

STEP 1 · 반복 업무 분해
본인 워크플로 분해 항목
칸적기
업무 이름예: "PR 전 셀프 리뷰 체크"
입력변경 diff, 기능 스펙
반복 단계린트→테스트→정책체크→요약
자동화 후보정책체크, 변경 요약
사람 판단최종 수용, 보안 영향
중단 조건동일 실패 2회 → 사람 리뷰(HE-08)
STEP 2 · 제약 → 체크로 코드화
"이 작업은 반드시: ① 외부 패키지 추가 금지 ② public API 시그니처 불변
③ 커버리지 하락 금지. 각 항목을 검사하는 로컬 체크를 만들고, 위반 시 중단."

자연어 제약을 policy-check 규칙·테스트로 옮기는 연습입니다.

STEP 3 · 내 업무용 Loop 설계

Plan→Generate→Evaluate→Fix→Gate를 내 업무 용어로 다시 씁니다. 각 단계의 stop condition과 owner를 명시합니다.

참조 심화 — 장기 실행 안전장치

반복 업무가 수 시간~수 일로 길어지면(배치 리서치·문서 처리·AIOps) 단일 블랙박스 실행이 아니라 체크포인트 + 사람 승인 사슬로 운영합니다.

Loop 오케스트레이션

Collect→Normalize→Generate→Validate→Approve→Reflect

체크포인트 & 산출물

산출물: 본인용 하네스 워크플로 캔버스 + Agent Teams/Fleet Loop 초안(중단 조건·owner 포함).
  • 자동화 후보와 사람 판단이 분리되었는가?
  • 모든 Loop 단계에 중단 조건이 있는가?
  • 최소 1개의 자연어 제약이 체크/테스트로 코드화되었는가?
컷라인: 반복 업무 1개 + 자동화 후보 1개 + 중단 조건만 있으면 통과. 완전한 Loop는 S6에서 보강 가능.

흔한 실수 & 공유 포인트

  • 너무 큰 업무를 고름 → 50분에 안 끝남. "한 번에 하는 작은 반복"을 고릅니다.
  • 전부 자동화하려 함 → 사람 판단 지점을 남겨야 안전합니다.
공유 포인트: "내가 자동화하기로 한 반복 업무 1개"를 한 문장으로. 이것이 S7 라이트닝 토크의 핵심 슬라이드가 됩니다.
