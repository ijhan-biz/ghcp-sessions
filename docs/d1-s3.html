좋은 프롬프트 (2) — 리팩토링·복잡 로직과 Context Manifest

동작을 바꾸지 않으면서 코드를 정리하는 리팩토링과 분기가 많은 복잡 로직을 안전하게 지시하는 법, 그리고 봐야 할 파일만 추리는 Context Manifest로 토큰과 데이터 경계를 동시에 잡는 법을 익힙니다.

SD-04 Context ManifestGN-06 작은 diffPT-10 출력 형식 제어PT-02 컨텍스트 관리OR-12 데이터 경계

학습 목표

  • "동작 불변"을 가드레일로 명시한 리팩토링 프롬프트를 작성한다.
  • 분기가 많은 복잡 로직을 작은 함수로 분리하도록 단계적으로 지시한다.
  • Context Manifest(allowed/blocked/unknown/test files)로 봐야 할 파일을 좁힌다(SD-04).
  • 결과가 빗나갈 때 실패 프롬프트 디버깅으로 한 가지씩 교정한다.

미니강의 — 리팩토링은 "동작 불변 + 작은 diff"

리팩토링의 핵심 가드레일은 두 가지입니다: 동작을 바꾸지 않는다(기존 테스트 모두 통과)와 작은 diff(GN-06, 1~2파일·소규모)입니다. 작은 diff는 리뷰와 롤백을 쉽게 만들어 Day2의 로컬 게이트와 직접 연결됩니다.

Context Manifest = 토큰 + 데이터 경계 (SD-04)

복잡 로직일수록 "어떤 파일을 봐야 하는가"가 모호해집니다. Context Manifest는 봐야 할 파일을 allowed, 건드리면 안 되는 파일을 blocked, 모르는 것을 unknown으로 명시합니다. 이것이 곧 토큰 절약이자 데이터 경계(OR-12)의 장치입니다.

실습 1 — 리팩토링·복잡 로직 프롬프트

리팩토링 프롬프트
[역할] 너는 billing feature 담당 개발자다.
[맥락] calcVat()에 면세 분기·음수 가드·예외 처리가 섞여 가독성이 낮다.
[작업] 동작 변경 없이 calcVat()를 리팩토링하고, 복잡 분기를 작은 함수로 분리.
[제약] 기존 public API 시그니처 유지, 외부 패키지 추가 금지, 기존 테스트 전부 통과.
[출력] 변경 diff 요약 → 코드 → 테스트 순서로.
실패 프롬프트 디버깅
  • 결과가 빗나가면 맥락·제약·출력 형식 중 무엇이 빠졌는지 점검하고, 한 번에 다 고치기보다 한 가지씩 조정합니다.
  • "왜 이렇게 했는지" 설명을 요구해 모델의 가정을 드러냅니다(잘못된 가정이 보입니다).

실습 2 — Context Manifest 작성

작성 프롬프트
[작업] 아래 기능 스펙을 구현하려면 어떤 파일만 보면 되는지 Context Manifest를 만들어라.
[포함] allowed files, blocked files, unknowns, test files, 민감정보 경계.
[제약] 파일명을 추정하지 말고, 모르면 탐색 질문으로 남겨라.
[출력] 표 형식.
구분예의미
allowedsrc/billing/tax.ts수정 허용
blocked.env, prod/*변경 금지(게이트로 강제)
testtax.test.ts검증 파일
unknown"환율 모듈 위치?"탐색 질문으로 남김
이 blocked 목록은 Day2·S2의 policy-check(HE-04)가 자동 감지하는 대상이 됩니다.

체크포인트 & 산출물

산출물: ① 리팩토링/복잡 로직 프롬프트 1개, ② 구현 계획·테스트 생성 프롬프트, ③ Context Manifest v1.
  • 리팩토링 프롬프트에 "동작 불변 + 기존 테스트 통과"가 있는가?
  • Context Manifest에 allowed/blocked/test가 분리되어 있는가?
  • 실패 시 한 가지씩 교정한 로그가 있는가?
컷라인: 복잡 로직 분리가 어려우면 리팩토링 프롬프트 1개 + Context Manifest 1개로 충분합니다.

흔한 실수 & 공유 포인트

  • 리팩토링하면서 기능까지 추가 → 동작이 바뀌어 회귀 발생. 리팩토링과 기능 추가는 분리합니다.
  • Context Manifest 없이 큰 변경 → 엉뚱한 파일 수정. 먼저 범위를 못박습니다.
공유 포인트: "내 코드에서 Context Manifest가 막아준 위험" 한 줄. 데이터 경계 사례는 팀 보안 관점에서 공유 가치가 큽니다.
